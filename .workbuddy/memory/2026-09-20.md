## 阅读区文字改为「可选中可复制」（v0.3.2）

- **根因**：`AssistantPageView.ParagraphPane`（JTextPane 子类）显式设了 `setFocusable(false)`——不可聚焦的文本组件无法建立选区，所以正文怎么拖都选不中。
- **改法**：新增 `AssistantTheme.makeSelectable(JTextComponent)` 统一配置只读文本：可聚焦 + 文本光标 + 隐藏插入符（覆盖只画插入符的 `DefaultCaret.paint(Graphics)`，选区高亮走另一个重载，不受影响）+ "复制 / 全选"右键菜单。
  - 多行的段落/话术仍用 `ParagraphPane`；**单行**的代码行、shell 命令行、小标题换成新的 `AssistantTheme.SelectableText`（JTextField 子类：不折行，且重写 `getPreferredSize()` 按字体度量返回，与原来的 JLabel 逐像素一致）。卡片头部的文件名 `FileNameLabel` 保持 JLabel（它参与三级降级的宽度预算）。
- **副作用与处理**：正文可聚焦后排在输入框前面，工具窗口激活时焦点会落到正文上 → "打开面板直接按 ↑/↓ 或打字"失效。`ChatInputBar` 暴露 `inputComponent()`，`MainUi` 用 `content.setPreferredFocusableComponent(...)` 把初始焦点交回输入框。
- **验证**：本机 Gradle 缓存不存在且 Clash 代理未开（7890 拒绝连接），改走 IDEA 自带 `jbr/bin/javac.exe`（Java 25；平台 class 是字节码 69，JDK 17/21 读不了）+ IDEA `lib/*` 编译校验，除 epublib 缺失的 `EpubUtil/MainUi/Setting/ShowThiefBook` 外零错误。
  - 新增 `SelectCheck.java`：真实渲染一页 → 17 个文本组件全部 focusable、editable=false、选区可读回 ✓
  - 新增 `PngDiff.java` 做改动前后像素对比：8 张预览图 7 张逐像素完全一致；唯一差异是输入框的初始插入符（见上一条副作用）。
  - 顺手修好 `UiPreview.java`（内部 `render` 重载只声明到 5/7/9 个参数、调用点却传 8 个，一直编译不过）。
